# Прямая доставка музыкального дневника в конкретный чат ChatGPT

**Статус:** обязательное требование релиза 1.0; способ доставки ещё не выбран и не реализован.  
**Зафиксировано:** 26 ноября 2026 года.

## Требование Кати

События музыкального дневника должны автоматически поступать **в один конкретный уже существующий чат ChatGPT**, предназначенный для обсуждения музыки.

Не подходят:
- создание нового чата на каждую отправку;
- запись только в файл, Google Drive или внутреннюю почту «Чанти Моста»;
- ручное копирование/вставка или ручная пересылка;
- доставка музыкальных событий в чат «Миры Магира».

После однократной настройки маршрута обычное прослушивание не должно требовать дополнительных действий.

## Что уже есть в коде приложения

- `MusicListenerService` получает Android MediaSession и уведомления поддерживаемых плееров.
- `MediaScan` отбирает Яндекс Музыку и выбранные видеоплееры.
- `TrackStore` локально хранит начало/смену трека, паузу/возобновление, длительность и рейтинг только при наличии реального события рейтинга.
- `VideoStore` хранит доступные метаданные видео, не считывая видеоряд.
- `MainActivity.copyDiary()` сейчас только собирает текст, кладёт его в буфер обмена и предлагает открыть ChatGPT. `openChat()` запускает приложение ChatGPT или общий сайт, но не конкретный диалог.

Следовательно, сбор событий уже существует, а автоматическая доставка в целевой диалог отсутствует.

## Что найдено в «Чанти Мосте 1.0/1.1»

В таблице есть активные маршруты проекта `music` и получателя `music` («Чанти — музыка»). Это подходящие внутренние обозначения маршрута, но не идентификатор конкретного диалога ChatGPT.

Текущая внешняя интеграция Алисы ограничена в Apps Script агентом `alice` и проектом `general`; Cloudflare Worker также отправляет события с этими значениями. Готового маршрута Android-приложения к получателю `music` пока нет.

Внутренняя запись в таблицу «Почта» моста сама по себе не считается выполнением требования Кати: это лишь транспорт/очередь, а не сообщение в целевом чате.

## Проверка официальных интерфейсов OpenAI

1. В публичной документации ChatGPT Android описаны просмотр истории и повторное открытие существующих диалогов, но не документирован API для добавления сообщения в произвольный существующий пользовательский чат.
2. OpenAI API предоставляет Conversations API, включая добавление items в `/v1/conversations/{conversation_id}/items`. Это API-управляемая беседа с API conversation ID; документация не указывает, что этот ID является чатом из пользовательской истории ChatGPT. Поэтому этот API нельзя выдавать за решение задачи с существующим чатом Кати.
3. Event-triggered tasks в ChatGPT Work реагируют на поддерживаемые события Gmail, Slack и GitHub и выполняются в Work. В документации не заявлена возможность принять произвольный webhook от «Чанти Моста» и записать сообщение в заданный существующий обычный чат ChatGPT.

Ссылки:
- https://help.openai.com/en/articles/8142208-chatgpt-ios-and-android-app-faq
- https://developers.openai.com/api/reference/resources/conversations/subresources/items/methods/create
- https://help.openai.com/en/articles/10291617-scheduled-tasks-in-chatgpt

**Вывод на дату проверки:** среди проверенных публично документированных интерфейсов нет подтверждённого способа автоматически добавлять сообщения из Android-приложения в конкретный существующий пользовательский чат ChatGPT. Не использовать внутренние/недокументированные API приложения ChatGPT, извлечение его токенов или обход защиты.

## Возможное направление исследования — не утверждённое решение

Проверить локальный Windows-компонент (например, расширение браузера или companion-программа), который работает в уже авторизованном ChatGPT Web, привязывается к одному конкретному URL диалога и отправляет туда события через пользовательский интерфейс.

До выбора этого направления требуется проверить:
- можно ли надёжно отправлять сообщения именно в зафиксированный диалог, не создавая новый;
- требования к включённому ПК, браузеру и активной авторизации;
- устойчивость к изменениям интерфейса ChatGPT;
- безопасность и допустимость такой автоматизации;
- поведение при закрытом браузере, отключённом ПК и потере сети.

Это только гипотеза для исследования, а не обещание и не готовая реализация.

## Критерии приёмки

- Маршрут привязан к одному конкретному существующему чату и не меняется сам.
- Новые события появляются именно в этом диалоге как сообщения, доступные Чанти для обсуждения.
- Не создаются новые чаты и не требуется ручное копирование.
- Повторная доставка не создаёт дубликаты; при отсутствии сети события сохраняются и отправляются после восстановления связи.
- Музыка и «Миры Магира» имеют независимые адресаты и очереди.
- Система честно сообщает о доставке/ошибке; «принято мостом» не выдаётся за «появилось в чате».
- До успешного теста на реальном целевом чате функция не считается готовой, а релиз 1.0 не объявляется полностью соответствующим требованию.
